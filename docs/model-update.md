# モデルの追加・差し替えと色の更新

## 配置と設定

公開一覧は `public/catalog.json` です。モデル ID は共有 URL の `?model=` に使い、`config` は `public/` からの相対パスです。

| ID | 設定ファイル | 3MF ファイル | 幅 × 奥行 × 高さ（mm） / ボディ数 / 三角形数 |
| --- | --- | --- | --- |
| `figure-stand` | `public/viewer.json` | `public/models/figure-stand.3mf` | 1000 × 40 × 1500 / 1 / 68 |
| `pillar-decoration` | `public/models/pillar-decoration.json` | `public/models/pillar-decoration.3mf` | 975 × 845 × 1990 / 4 / 348 |
| `signage` | `public/models/signage.json` | `public/models/signage.3mf` | 940 × 930 × 2141.86 / 31 / 1876 |

1. Fusion から対象のモデルを 3MF として書き出し、単位・上方向・正面方向と実寸を控えます。メッシュには CAD の履歴や BRep は含まれません。
2. 対象の `public/models/*.3mf` を差し替えます。新規追加なら別名で配置し、`public/models/<id>.json` を既存の設定を参考に作成し、`public/catalog.json` に固有の ID・表示名・設定パスを追加します。ブラウザからの一般モデルアップロード機能はありません。
3. 設定の `model` を `public/` からの相対パスで指定し、`title`、`description`、`updatedAt`、`upAxis`、`frontAxis` を確認します。人形立ては Z が上・X が正面、柱装飾とサイネージは Z が上・Y が正面です。
4. `npm run dev` または `npm run dev:admin` で開き、「モデルを選択」と共有 URL を確認します。ローダーは 3MF の単位を読み取り mm に換算します。寸法が想定と違う場合は、書き出し時の単位と軸を確認してください。複数の外部モデル部品を参照する 3MF は未対応です。Fusion から通常の 3MF として書き出してください。
5. ボディ一覧と色を確認します。同名のボディは UI で番号を付けて区別します。ID は build 項目と object ID、コンポーネントの階層・インデックスなどから構成されます。再書き出しで ID が変わる場合があるため、既存の `colors` を流用する際は新しいボディとの対応を確認します。名前だけで対応付けないでください。
6. 寸法付き図面の正面・右側面・平面、全ボディ寸法一覧、個別部品と辺の3D実長を確認します。3D画面で非表示にしたボディも図面に含まれます。図面と測定値はメッシュの近似で、隠線処理・CAD 公差・加工寸法を保証しません。
7. `npm test`、`npm run build`、必要に応じて `npm run test:e2e` を実行し、ブラウザで表示・タッチ操作・図面保存・測定を確認します。実機の iPhone Safari でも確認してください。Chromium のスマートフォンエミュレーションだけでは実機確認になりません。

人形立ての元の X / Y / Z は 40 / 1000 / 1500 mm、ボディ `ボディ2` の ID は `build:0/object:1` です。モデル差し替え後はこの文書と README の基準値も更新してください。

## 色を3MF本体に保存する

`npm run dev:admin` でモデルを選択し、「色を編集（開発者用）」を開きます。色をプレビューして「設定を保存」を押すと、選択中の 3MF の材料・色の XML に反映します。形状は保持し、対応する設定の `colors` は空になります。保存前の 3MF は `.local/backups/` に保存されます。色だけの更新なら Fusion からの再書き出しは不要です。

「読込時の色」はページで読み込んだ時点のモデルの色を戻す操作です。同じページ内で保存した後もその基準を使い、再読み込みすると保存後の色が新たな基準になります。以前の版へ戻す際はバックアップや Git の履歴を使用してください。「設定ファイルをダウンロード」は JSON の控えで、3MF 本体のバックアップではありません。

モデル・設定が外部で更新された場合は保存を拒否します。最新状態を確認して再読み込みし、編集し直してください。公開ビルドにはこの編集 UI や保存・同期ルートは含まれません。

## GitHub に反映する

色の保存と GitHub への反映は別操作です。「GitHubへ同期」はインストール済みの Git と既存の認証を使い、選択中の 3MF と設定ファイルだけをステージ・コミットし、`origin` の現在のブランチに push します。Git のコミットユーザーと push 権限が必要で、HTTPS 接続は設定済みの Git 認証を使用します。未保存の色変更は先に保存してください。

他のファイルがステージ済みなら同期を拒否します。該当のステージを解除するか別途コミットしてから実行します。自動 pull と force push は行いません。リモートの更新で push が拒否された場合は、通常の Git 操作で pull・競合解消を行い、ページを再読み込みしてから再実行してください。push 失敗時もローカルコミットが残る場合があるため、Git の状態を確認します。

新しいモデルの追加で変更した `public/catalog.json`、ドキュメントなどは同期ボタンの対象外です。通常の Git 操作で必要な変更一式をコミット・push してください。`main` に反映すると Pages ワークフローが実行されます。Actions のデプロイ完了後、公開 URL で対象モデルを直接開いて確認します。

## 測定結果への影響

2点間の測定結果は同じブラウザの `localStorage` に、モデルファイルのハッシュと向きごとに保存されます。再読み込みやモデル切り替えでは復元されますが、3MF の差し替え・色の保存・軸の変更で対象のキーが変わると、以前の測定結果は新しいモデルに引き継がれません。測定結果はリポジトリに保存されず、公開や GitHub 同期の対象にもなりません。
